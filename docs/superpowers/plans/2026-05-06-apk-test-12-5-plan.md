# APK Test #12.5 — PRO unlock systemic fix + library-aware logging_type

**Date:** 2026-05-06
**Branch:** `feat/apk-test-12-5-batch`
**Triggered by:** founder install of APK 12.4 surfaced 3 critical bugs after on-device QA.

## Founder observations (from APK 12.4 install)

1. **Couldn't upgrade to PRO** — generic "Couldn't start payment" toast on tap (server returned 409 already_pro per logs).
2. **Push Up + Hanging Leg Raise rendered as "secs"** in receipt; `bodyweight_reps` exercises stamped with `logging_type='timed'`.
3. **Train calendar expanded view still shows "0s"** — same root cause as #2.

## SoT analysis (writers + readers per concept)

### A. `exlog_*.logging_type`
- **Writers:** `WorkoutWriteService._inferLoggingType` (data-shape only, no library) ← BUG; `LoggingTypeRepairMigrator` (library-strict for top-level only); `SyncService` cloud→Hive projection.
- **Readers:** `WorkoutReceiptCard`, `train_screen.dart:846` `_buildExpandedExercises`, `train_screen.dart:1110+` bottom sheet, `WardSetChips`, `EditWorkoutLogSheet`, `ai_coach_repository`.

### B. PRO subscription state (`isPro` Hive)
- **Writers:** `SubscriptionService.writeSubscriptionState`, `_downgradeLocally`, `RazorpayService._handlePaymentSuccess`.
- **Readers:** `isPro()`, `subscriptionInfoProvider`, ~25 widget watchers + service callsites.
- **Reactivity:** `app.dart:40` wires `onStateChanged`.

### C. `create-razorpay-order` 409 response handling
- **Server writer:** `create-razorpay-order/index.ts:108-118` returns 409 with `error_code: 'already_pro'`.
- **Client readers (TWO competing):** `razorpay_service.dart:105` (DEAD code — never executes) vs `razorpay_service.dart:153` catch block (always fires due to supabase_flutter's `invoke` throwing on non-2xx).

### D. Per-set `durationSec` field
- **Writers:** `active_workout_screen.dart:1264` (`SetInputValues.durationSeconds`); `train_provider.dart:1384`; `WorkoutWriteService` persistence.
- **Readers:** `WardSetChips`, receipt, edit sheet — all branch on resolved logging_type.

## Work plan (5 classes, no deferrals)

### Class 1 — Writer-side library awareness (Obs 2, 3 root cause)
- 1a. `WorkoutWriteService._inferLoggingType` → `_resolveLoggingType(name, sets)` that consults `exerciseBox` first; data-shape fallback only for custom exercises.
- 1b. When resolved type ≠ `'timed'`, strip `durationSec` from per-set entries on write.
- 1c. Bump `LoggingTypeRepairMigrator` flag `_v2_done` → `_v3_done` + add per-set migration to `bodyweight_reps` branch (mirror of `timed` branch).

### Class 2 — Edge function invoke error handling (Obs 1 root cause)
- 2a. `razorpay_service.dart:105-131` 409 detection moves into the catch block. Parses `FunctionException.status == 409` + `details['error_code']`.
- 2b. `_showOrderCreationFailure` reads server's `error` field when available; falls back to generic copy.

### Class 3 — Subscription state hardening
- 3. `refreshFromSupabase` catch block posts to `log-client-error` (with request_id) so we can see when sync silently fails for users.

### Class 4 — Diagnostic instrument
- 4. Active workout `completeWorkout` logs `[durationCtl] {exerciseName, slotLoggingType, ctlText}` for every non-timed slot whose duration controller is non-empty. Read in next install's logs.

### Class 5 — Contract tests
- 5a. `test/contracts/workout_write_logging_type_library_test.dart` — pin: Push Up + stuffed durationSec → resolved `bodyweight_reps`, per-set durationSec stripped.
- 5b. `test/contracts/razorpay_409_already_pro_test.dart` — pin: FunctionException status=409 + error_code=already_pro routes to PRO toast, not order-failure toast.
- 5c. `test/safety/logging_type_repair_migrator_v3_test.dart` — pin: bodyweight_reps row with stuffed per-set durationSec → per-set entries migrated.
