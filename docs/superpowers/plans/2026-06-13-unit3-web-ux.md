## Fix 1 — obs 2b: Health Connect web dead-end (the one clear current-code bug)
**Symptom:** on web, tapping CONNECT on the Health Sync card calls the native Health Connect / HealthKit
permission flow, which has no web binding → "stuck on health connect page."
**Path:** profile Health Sync sheet → `BiometricSyncCard.onToggleSync` → `biometricProvider.toggleSync(true)`
→ `HealthSyncService.instance.requestPermissions()` (`profile_provider.dart:507-510`, native-only).
**Fix (two layers):**
1. **Functional boundary** — in `HealthSyncService` (the native seam), early-return on `kIsWeb` in ALL FOUR
   public methods that call the native `Health()` via `_ensureConfigured()` (verified — review #1 Finding 1):
   `requestPermissions()` (`:46`) → `false`; `fetchStepsToday()` (`:87`) → `null`; `fetchLatestWeight()`
   (`:107`) → `null`; `syncToHive()` (`:143`) → no-op return. `isEnabled()` (`:209`, static, reads a Hive
   bool) needs NO guard. Gating only 3 of 4 leaves a `MissingPluginException` path on web.
2. **UI entry** — gate the Health Sync entry on `kIsWeb`: the profile Settings health row + the
   `BiometricSyncCard` CONNECT button render a disabled "Health sync is mobile-only — install the app"
   state on web instead of the live toggle. (Mirror any home step-counter entry that triggers the native
   path; the home steps card is display-only of already-synced data, so it just shows `--` on web — verify.)
**Entry points to cover (verify all in review):** `profile_provider.toggleSync`, `health_sync_sheet.dart`,
`biometric_sync_card.dart`, home step counter, `splash_screen` auto-sync (must not call native on web).
`lib/features/dev/simulation_service.dart` is debug-only — out of scope.

## Fix 2 — obs 2: share-card quote keyed to the workout's exercises, not just its name
**Symptom:** a custom-named workout ("test template") → the quote category is derived from the NAME
(`QuotePicker.categoryForWorkout(data.workoutName)`, `workout_receipt_card.dart:627`), which has no muscle
keyword → a generic/odd ("lat") quote that doesn't match what was trained.
**Fix:** add `QuotePicker.categoryForExercises(List<String> exerciseNames)` — map each name through the
existing keyword logic (reuse `categoryForWorkout`'s rules) and return the **most common** category, falling
back to `categoryForWorkout(workoutName)`, then `'general'`. `ReceiptExercise` carries `name` (no category
field — names are the signal; `workout_receipt_card.dart:526-533`). The receipt card passes
`data.exercises.map((e) => e.name)`. Deterministic seed unchanged (`data.taglineSeed` excludes exercise
names — verified safe, review #1 Finding 3).
**Explicit edits (review #1 Findings 2+4):**
- `_pickTagline`'s SIGNATURE changes `(String workoutName, int seed)` → `(List<String> exerciseNames, int seed)`.
  BOTH call sites update: the `WorkoutReceiptData` construction at `workout_receipt_card.dart:506-509` (pass
  `exerciseList.map((e) => e.name).toList()`) AND the body.
- The exercise→category voting logic must be a SHARED function (extract once, used by both the async
  `QuotePicker.pickForCategory` path and the sync `_pickTagline` fallback) — do NOT duplicate it as a new
  inline switch. `_pickTagline` currently lacks `full_body`/`arms` branches that `categoryForWorkout` has;
  sharing the logic closes that pre-existing loading-vs-settled mismatch instead of perpetuating it.
- Keep `categoryForWorkout` (still the name-based fallback). Pure-function change — fully unit-testable.

## Fix 3 — obs 6: PWA install banner (web-only feature-add)
`manifest.json` exists; add a custom install prompt:
1. **`web/index.html`** — small inline script: capture `beforeinstallprompt` into a global +
   `e.preventDefault()`; listen for `appinstalled`. Expose `window.avyaPwaCanInstall()` → bool and
   `window.avyaPwaPromptInstall()` → calls the stashed `prompt()`.
2. **Flutter (web-only)** — a `PwaInstallBanner` widget (dismissible, Wardroom-styled, "Install
   ICANBEFITTER — add to your home screen") shown on Home below the header. Guards: `kIsWeb` only; render
   only when `avyaPwaCanInstall()`; once-dismissed persists (`configBox['pwa_banner_dismissed']`, user-scoped
   via `UserConfigMigrator` if needed — but it's a device/web preference, not user data; a plain config flag
   is fine). On tap → `avyaPwaPromptInstall()`. **iOS Safari** (no `beforeinstallprompt`): detect iOS Safari
   → show a one-line "tap Share → Add to Home Screen" hint instead of the install button.
   **JS-interop (review #1 Findings 6+7):** web-only conditional import keyed `if (dart.library.js_interop)`
   — a `pwa_install_io.dart` stub (`canInstall=false`, no-op) + `pwa_install_web.dart` (`@JS` externals via
   `dart:js_interop`). Do NOT mirror `lib/features/dev/plan_xls.dart`'s legacy `dart.library.html` key
   (deprecated + risks the `avoid_web_libraries_in_flutter` lint). The banner widget is `kIsWeb`-gated AND
   `canInstall`-gated → never renders in the Android app, never breaks the `app.dart` phone-frame.
   Add the dismiss flag `pwa_banner_dismissed` to `UserConfigMigrator._intentionallyShared` (`:109`, alongside
   `pending_referral_code`) so the "unscoped configBox key" audit doesn't flag it (it's a per-device/browser
   preference, not user data).

- A: `splash_screen.dart:136` is ALREADY `if (!kIsWeb && HealthSyncService.isEnabled())` before

  `pwa_install_web.dart` with the `@JS` externals) so the Android/iOS build never references web interop.
- C: PWA-dismiss flag in `configBox` is fine — it's a per-device/web preference, not user data. Keep it
  un-scoped but namespaced (`pwa_banner_dismissed`); a shared-browser "leak" only re-hides an install banner,
  no privacy impact. (Reviewer: confirm that's acceptable vs user-scoping.)
