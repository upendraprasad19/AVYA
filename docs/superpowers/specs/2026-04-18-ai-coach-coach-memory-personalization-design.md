# AI Coach — Hyper-Personalization (Layers 4 + 5) + `coach_memory`

## Context

The user spent meaningful time on a 688-line research doc at `Knowledgebase/AI_COACH_BRAINSTORM.md` proposing a richer AI coach. After comparing the doc against the live system, most "obvious" features (voice, body-fat photo, food photo, morning alert, nightly summary, heuristic notes) are **already shipped** — but two layers of the brainstorm's personalization vision are missing:

- **Layer 4 — Predictive signals:** dropout risk, plateau prediction, PRO-upgrade probability
- **Layer 5 — Identity mirroring:** Hinglish detection, preferred name, humor tolerance, depth preference, motivation style

Both depend on a structured **`coach_memory`** record that today doesn't exist — current state is a list of up to 20 free-text strings in Hive (`coachBox['coaching_notes']`) generated by a brittle keyword scanner. The Edge Function `daily-snapshot` already does Gemini-based extraction of *some* structured fields (diet, injuries, lifestyle, food prefs, supplements) into `user_profile` + `user_preferences.coaching_notes`, so the extraction pipeline exists — it just needs more fields and a proper home.

**Outcome:** Coach responses become noticeably personal — knows the user's name, mirrors language, references real risk signals — without the user ever filling out a form.

User decided (in brainstorm): focus area = Hyper-personalization + coach_memory. Scope = full design, single ship.

## Decisions Made During Brainstorm

| Question | Decision | Why |
|---|---|---|
| New `coach_memory` table or extend `user_preferences`? | **New dedicated table.** | 1-row-per-user, queried by every AI call + cron jobs. Keeps `user_preferences` focused on user-set toggles. Matches brainstorm doc. |
| Extraction: Gemini or heuristic? | **Hybrid.** Heuristic (instant, on-send) for cheap signals — Hinglish, name. Gemini (nightly, in `daily-snapshot`) for nuanced fields — humor tolerance, depth preference, motivation style. | Avoids per-message Gemini cost; matches existing pipeline. |
| Predictive signals: who computes? | **New nightly cron Edge Function `compute-coach-signals`** — pure SQL over `workout_logs`, `weight_logs`, `ai_coach_interactions`, `subscriptions`. Writes scores to `coach_memory`. | No AI cost. Deterministic. Re-runnable. |
| Cadence | Memory extraction: nightly (piggyback on existing `daily-snapshot`). Signals: nightly. Identity heuristics: per-message (client-side). | Simple cron, single source of truth. |
| Hive mirror | **Yes.** `coachBox` key `coach_memory` mirrors server row, refreshed on every snapshot push round-trip. | Client-side `buildAiContext` needs offline-first read. |
| Privacy | Add `consent_version` and `private_mode` columns now. UI toggle deferred. | Cheap to add, painful to retrofit. |
| Migration of existing data | Backfill existing `coachBox['coaching_notes']` strings + `user_profile` fields into new `coach_memory.coach_notes` and structured fields on first read. Then deprecate the legacy 20-string list. | Zero data loss. |

## System Prompt — Restructured to Brainstorm's 7-Block Spec

`AiCoachRepository.buildAiContext()` returns a JSON shaped like brainstorm §13:

```
[1] IDENTITY & RULES         (static — coach personality, hard rules)
[2] USER PROFILE             (existing — name, age, goal, equipment)
[3] COACH MEMORY             (NEW — full coach_memory row)
[4] TODAY'S CONTEXT          (existing — workout, nutrition, sleep, steps)
[5] RECENT HISTORY           (existing — fitness_summary + last 5 turns)
[6] AVAILABLE TOOLS          (deferred — placeholder for tool-calling phase)
[7] RESPONSE RULES           (static — 2-3 sentences, one question, mirror style)
```

Block [3] adds these instructions to the system prompt:

```
The user prefers to be called "{preferred_name}".
They communicate in {communication_style} — mirror that.
They are a {depth_preference} — keep replies {short|with reasoning}.
Their motivation style is {motivation_style} — {tone guidance}.
Risk signals: dropout={dropout_risk_score}, plateau={plateau_risk_score}.
Last proactive nudge: {last_proactive_type} — do not repeat this type today.
```

Hard cap remains 9.5 KB (existing trim order in `_compactContext` already drops least-load-bearing fields first; `coach_memory` slots between `coaching_notes` and `personal_records` in trim priority — keep before nutrition/exercise history is dropped).

## Predictive Signal Formulas (v1 — deliberately simple)

```sql
-- dropout_risk_score: 0.0 (engaged) → 1.0 (likely churned)
WITH recent AS (
  SELECT
    -- workouts this week vs trailing 4-week average
    (SELECT count(*) FROM workout_logs WHERE user_id=$1 AND date >= now() - interval '7 days') AS w_now,
    (SELECT count(*) FROM workout_logs WHERE user_id=$1 AND date >= now() - interval '35 days' AND date < now() - interval '7 days')::float / 4 AS w_avg,
    (SELECT extract(day FROM now() - max(created_at)) FROM ai_coach_interactions WHERE user_id=$1) AS days_silent,
    (SELECT extract(day FROM now() - max(date)) FROM weight_logs WHERE user_id=$1) AS days_no_weigh,
    (SELECT avg(hours) FROM sleep_logs WHERE user_id=$1 AND date >= now() - interval '7 days') AS sleep_avg
)
SELECT least(1.0,
  0.4 * greatest(0, (w_avg - w_now) / nullif(w_avg, 0))
+ 0.3 * least(1.0, days_silent / 7.0)
+ 0.2 * least(1.0, days_no_weigh / 14.0)
+ 0.1 * greatest(0, (6.0 - coalesce(sleep_avg, 7)) / 6.0)
) FROM recent;

-- plateau_risk_score: weight unchanged + caloric surplus + plan stale
-- Simple: 1.0 if weight delta < 0.3kg over last 10 days AND avg daily calories > target+100,
--         scaled down if either is false.

-- pro_upgrade_probability: trial_days_remaining < 8 AND msg_volume > 10/day AND streak > 15
-- Discrete buckets, no fancy math at v1.
```

These are starting points. v2 can replace with logistic regression once we have ~3 months of churn labels — but **not in this ship**.

## Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Gemini extraction adds latency to `daily-snapshot` | Already async (fire-and-forget) in current code. Timebox extra fields to single Gemini call (no separate round-trip). |
| Heuristic Hinglish detection misfires (Romanized English mistaken for Hinglish) | Require ≥2 Hindi-stem words in message before flipping flag. Sticky preference — only changes after 3 consecutive same-style messages. |
| Predictive signal false positives annoy users | v1 signals are stored but **not surfaced as nudges** in this ship — they only enrich the system prompt. Proactive triggers using these scores ship in the next plan. |
| Coach memory bloats Hive | Single row per user, ~2 KB max. Negligible. |
| Snapshot exceeds 9.5 KB more often | `coach_memory` adds ~800 bytes. Trim order updated; older fields drop first. Add telemetry on compaction events to `client_errors` if it becomes routine. |
| Privacy regression | `private_mode=true` short-circuits extraction in `daily-snapshot` and skips fetch in `ai-proxy`. Column exists; toggle UI deferred but enforcement built-in from day one. |
