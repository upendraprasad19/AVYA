## Finding 1 — P2 — test_adequacy (rotation-specific lens F)

- **File:** `test/contracts/plateau_rotation_behavioral_test.dart:246-263` ("both-coherence" test).
- **Claim:** The trailing assertion (`expect(e.sets, lessThanOrEqualTo(20));` at line 259, looped over every exercise in every day/week) is meant to prove "Group sets stay MRV-bounded" (line 255 comment) when rung-2 (+set) and rung-3 (rotation) fire together.
- **Verification:** Read `volume_titration.dart:41-42` (`_mevPerWeek=8`, `_mrvPerWeek=20`) and `:154-204` (`applyToWeeks`/`_titrateWeek`/`_applyBump`). The MRV clamp (`weeklyBase < _mrvPerWeek`, line 185) is evaluated on the **per-major-muscle-group weekly aggregate** (`weeklyBase`, summed across all matching exercises that week), and even when a bump fires, `_applyBump` (lines 218-246) adjusts exactly **one** exercise's `.sets` by ±1 off a base that's almost always 3-5 (library `default_sets`). A single exercise's `.sets` field can therefore never realistically approach 20 in one generation pass, regardless of whether the group-level clamp logic is correct, off-by-one, or entirely removed. The assertion at line 259 is checking the wrong axis (per-exercise vs. per-group-weekly) and would pass unconditionally.
- **Impact:** Low. The test's *primary* assertion in the same test (line 254 — the target compound is still rotated out with titration ON) is sound and non-vacuous; only the secondary "coherence" bound-check is toothless. Does not mask a real defect in the shipped code (I independently confirmed the MRV clamp logic itself is correct by reading `volume_titration.dart`).
- **Suggested fix (non-blocking):** Replace the per-exercise check with a per-(day, group) weekly-aggregate sum assertion `<= 20`, mirroring `weeklyBase` in `_titrateWeek`.
