## What this pass taught (also appended to the code-review tuning history)

1. **A test written from the same mental model as the code cannot see the regression that does not fit that model.** Round A's 33 mutants were all "the way the code would be edited" and all went red; reviewer B's were "the way a regression sneaks in" (comment it out, add a second door, split the card, swap two names) and 13 of 21 stayed green. When mutating one's own new pins, pick the MIRROR-side mutants first.
2. **A source-grep pin must say what it reads.** Three new Profile-source tests read comments as code although the repo already had `readScreenSourceStripped`, written after the 2026-09-22 B-pass for exactly this. A recurrence of a known class; the helper now has a single-file twin.
3. **A count is not a position.** `allMatches(guard).length == 2` stays green for a guard after the push, on another row, or around nothing.
4. **A loop over tiers inside one `testWidgets` can silently test one tier**: a second `pumpWidget` does not apply a changed `overrideWith`.
5. **A sentence that justifies the next door is a defect.** "Each destination keeps its own gate" was false and read as permission for a second entry; say where the ONE gate is.
6. **Know what the test clock does.** `pump` flushes pending microtasks before it builds a frame, so "unmount, then let the callback run" needs the unmount done without a pump (`buildScope` + `finalizeTree`); that is what made the `onPro` guard testable after the plan had called it untestable.
