## Finding 1 — P2 — writer_reader_drift (value-semantics sweep gap)

- **file:line:** `supabase/functions/pr-detection/message.ts:16-18` (composeMessage interpolates `p.exercise_id` with no `exercise_name` fallback) + `supabase/functions/pr-detection/index.ts:86-93` (query had no `deleted_at` filter, no `exercise_name` select) + `supabase/migrations/151_workout_log_exercises_delete_trigger_insert_path.sql` (mutates `exercise_id` to `"<name> ‹del:xxxxxxxx›"` on delete)
- **claim:** OI-269's original text characterized all 5 un-patched `workout_log_exercises` readers as "not newly broken by 150/151... unchanged" — true for 4 of them, **false for `pr-detection`**. Because `composeMessage` renders `exercise_id` directly with no name fallback (unlike `i-see-you-callout`'s `exercise_name ?? exercise_id`), and the query had no `deleted_at` filter, a PR logged and deleted inside the same ~20-minute cron window would send a real push notification reading e.g. `"John — new Bench Press ‹del:a1b2c3d4› 100kg PR. Keep going 💪."` — a genuinely NEW, user-visible regression this batch's own exercise_id-suffix design introduced, in the exact class already recognized and fixed for weekly-recalc, mischaracterized here as out-of-scope.
- **verification:** `grep -n "exercise_id" supabase/functions/pr-detection/message.ts supabase/functions/pr-detection/index.ts` shows `composeMessage` uses `p.exercise_id` with no fallback and the select list never included `exercise_name` or `deleted_at`. Compare `i-see-you-callout/index.ts:264` (`exName = pr.exercise_name ?? pr.exercise_id ?? "that lift"`), which is safe.
- **suggested-fix:** Add `deleted_at` to the select and filter deleted rows out entirely before grouping/composing (mirroring `weekly-recalc/live_log_filter.ts`'s `excludeDeletedLogs` pattern), since notifying about a PR the user already deleted is wrong regardless of the display-garbling angle.
- **status:** accepted — fixed same session. Added `supabase/functions/pr-detection/live_pr_filter.ts` (`excludeDeletedPrs`, byte-identical pattern to `weekly-recalc/live_log_filter.ts`), wired into `index.ts` (select now includes `deleted_at`; `rawRows` filtered through `excludeDeletedPrs` before grouping-by-user). 5 new tests in `index_test.ts` (11 total in file, all green). Mutation-proven: reverting `const rows = excludeDeletedPrs(rawRows);` to `const rows = rawRows;` reddened exactly 1 of 11 (the wiring test); restored, 11/11 green. Type-checked clean (`deno check --node-modules-dir=none`). **Not yet deployed** — same founder-authorization-required caveat as the weekly-recalc fix (CLAUDE.md §4.3). OI-269 board entry corrected to move `pr-detection` from "5 remain, unchanged" to "fixed in this batch"; the other 4 readers were each individually re-verified (not assumed) to prefer `exercise_name` or read only numeric aggregates. See `docs/diagnoses/2026-09-28-exlog-tombstone-resurrection-e1c8b4.md`'s "Self-triggered B-pass code review, round 3" section for full detail.
