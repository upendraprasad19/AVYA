## Finding 3 — P2 — writer_reader_drift (write-path guard)
- **file:line:** lib/features/ai_coach/services/induction_service.dart:49, :124
- **claim:** `recordCommitment()` + `completeMuster()` lack the `currentOwnerFullId == null` guard applied to the read getters.
- **verification:** Read both methods — no guard; the new test covers only the getters.
- **status:** false_alarm (declined, with reason) — the asymmetry is intentional. The read getters needed the guard because the GoRouter **redirect** calls `inductionCompleted` pre-session; returning `false` is safe (re-evaluated once the session opens). `recordCommitment`/`completeMuster` are **writes** invoked only from the induction/muster screens (always post-auth/post-restore, session open). Adding a silent `return` guard to a write would risk **silent data loss** if ever mis-called — strictly worse than the current throw, which would surface the bug. Guard belongs on reads, not writes.
