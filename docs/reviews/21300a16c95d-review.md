## Finding 1 — P1 — function_exception_swallow / unawaited_no_error_sink — FIXED

- **file:line:** `lib/core/services/subscription_service.dart` — `gateAndVerify`, the
  `_highValueFeatures` branch.
- **claim:** The server-verified branch called `onPro()` / `onFree()` **directly inside the
  `.then()`**, with a trailing `.catchError` that calls `onPro()`. So `.catchError` guarded two
  unrelated things: a genuine `verifyFromServer` failure (where falling back to `onPro` is
  correct — local `isPro()` already returned true) **and a throw from the callbacks
  themselves**. The second case is an entitlement bug: a paywall sheet that throws makes
  `onFree()` fail, which lands in `.catchError`, which calls `onPro()` — **silently granting a
  PRO feature to a free user**. The same diff had just added `_runCallback` to fix exactly this
  swallowing on the *local* path, leaving the two paths asymmetric, and the new docstring's
  claim that "exactly one of onPro/onFree ran" was not true.
- **origin:** a defect in the **original 7b3eaf code** (2026-05-22), not a regression from this
  unit's split. This unit made it visible by asserting the exactly-once property.
- **verification:** `sed -n '/_highValueFeatures.contains(feature)/,/^    }/p' lib/core/services/subscription_service.dart`
- **fix applied:** callbacks now route through `_runCallback` (reports, does not rethrow, so a
  throwing callback can no longer reach `.catchError`), **plus** a `dispatched` latch that makes
  double-dispatch structurally impossible. Telemetry consolidated into the `dispatchOnce`
  emitter, which also removed a pre-existing lie: the timeout path used to log an
  `exit=onPro reason=verify_timeout` event and then fall through to log its real exit as well.
- **regression test:** `test/contracts/subscription_cqrs_behavioral_test.dart` group F — a
  throwing `onFree` must not run `onPro`, and must not propagate out of `gateAndVerify`.
- **status:** fixed
