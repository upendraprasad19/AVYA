## Findings, Flutter half

1. **The service wiring of the retry was unprotected.** The session compare, the
   "only end THIS order's grace" guard and the stop-after-first-verified latch lived as inline
   closures in `RazorpayService`, so deleting any of them reddened no test. **Fixed:** extracted
   `scheduleVerificationRetries` (injected scheduler) and pinned each guard; nine mutations
   (C1-C9) reddened by assertion, and `payment_grace_window_derived_wiring_test.dart` pins the
   service call site.
2. **The stated reason for the retry's side-effect order was wrong.** The comment claimed a stale
   in-flight `verifyFromServer` reply justified write-before-clear; it does not depend on order.
   **Fixed:** comment corrected in `payment_retry_attempt.dart`; the real reason (a throwing write
   leaves the grace open) is pinned by a test (mutation C6 clear-before-write: 3 reds).
3. **Wrong Hive key names in the diagnose-doc.** **Fixed:** `paymentInFlightOrder`.
4. **The session check ran only after the call, and Phase 1 wrote after its query without one.**
   **Fixed:** the check runs before the retry call too (mutation C5: 3 reds) and Phase 1 checks
   after its poll query.
5. **An over-broad "unbounded await" claim in the diagnose-doc.** **Fixed:** narrowed.
6. **The section 4.6 deviation (no kill-switch, no preserved old path) was undisclosed.**
   **Fixed:** disclosed in the diagnose-doc.

## Findings, EF/SQL half

7. **`pro_expired` / `free_users` in the migration draft did not match the plan** (a status-only
   reading versus "any subscriptions row and no live active one"). **Fixed:** the draft, the plan
   and both diagnose-docs now use any-status rows with `NOT EXISTS`; live numbers agree under
   either reading, so the migration-text test (Commit 2) pins the status set.
8. **The rollback block and header were wrong about the pre-152 bodies.** **Fixed:** exact live
   bodies for `extend_subscription`, the trigger function and `founder_metrics()`, captured with
   `pg_get_functiondef`. (A later Hermes pass also restored the orphan row in the rollback.)
9. **The per-consumer boundary flags were unpinned: five mutations survived** (digest 7d vs 30d,
   lapsed inclusivity, bot and admin windows). **Fixed:** boundary fixtures; D1-D4 now redden
   1 test each.
10. **`bot.py` failed silently.** `is_pro` swallowed errors into `False`. **Fixed:** fail-safe
    False with `logger.exception(...)`.
11. **The SoT reader entry was split wrongly.** **Fixed:** digest reader entries (915-940,
    1020-1042), telegram-admin-bot, expiry-reminder and the admin loader are separate entries;
    parity and Gate 42 pass.
