## P0 — broken paths or counters

- **P0-A · `AiBreakdownNotifier.saveMeal` early-return on null state** — `nutrition_provider.dart:733` returns silently if `state == null`. This happens after a successful save (line 764 sets `state = null`), so a double-tap on SAVE MEAL is silent. Also on widget-rebuild race (clear() then save()).
- **P0-B · Zero confirmation feedback on AI text save** — `ai_breakdown_card.dart:110-128` calls `saveMeal` but provides no snackbar, no haptic, no toast. The card disappears via `aiBreakdownProvider` becoming null. **Direct match for the user-reported bug**: the user typed text, analyzed, saw the breakdown, tapped SAVE MEAL — the card vanished and they had no signal whether the meal was logged. (Compare scan_meal `Meal saved ✓` line 449 and food_search_sheet `Logged $name` line 519.)
- **P0-C · `FoodLogNotifier.logFood` writes Hive without `items[]`** — `nutrition_provider.dart:790-835`. Cloud `_syncNutritionLogs` line 1257-1293 reads `log['items']` — for these legacy rows the key doesn't exist, so 0 rows hit `nutrition_log_items`. **Theme C of audit 1 + 3 confirmed.** Still live as of 2026-05-04 despite Test #10 deferral note.
- **P0-D · Legacy shape uses `food_name` not `items[].name`** — same path. Hive consumers (`AiCoachRepository._getMealsToday` post-Test #8 fix) tolerate it but cloud receivers don't.
- **P0-E · IST/UTC drift on counter reset & AI coach message count** — `usage_counter_service.dart:107` and `ai_coach_repository.dart:585` both use device-local `DateTime.now()` for the `todayStr`. CLAUDE.md `feedback_use_ist_throughout.md` mandates IST throughout. Theme B audit-1 finding.
- **P0-F · AI text counter increments on save, not on analyse** — `food_logger_section.dart:74-77` comment explicitly removed the `analyse()` increment. So a user analyzing 50 dishes without saving sees "50 remaining" client-side while the server has counted 50 against them via the Postgres trigger. Next analyse → 429 with no UI explanation.
- **P0-G · Scan counter increments on save, not on capture** — same class as P0-F. A user scans 5 photos but saves 0 → client says full remaining, but each scan hit the Gemini quota.
- **P0-H · Cart auditor never increments client counter** — there is no cloud write back through `NutritionWriteService` for cart auditor (it's an analysis-only feature). `UsageCounterService.increment(featureCartAuditorPro)` is enumerated in `_counterFeatureForSource` (`nutrition_write_service.dart:457`) BUT no code path passes `NutritionWriteSource.cart` to `logMeal`. Searched lib/: 0 hits. The only counter increment is dead code. UI display in `cart_auditor_section.dart:24` will show "1 remaining" forever for free users; abuse is gated only server-side.

## P1 — inconsistencies / UX issues

- **P1-A · `quantityG: 0` on AI text + scan + AI coach tool paths** — `nutrition_provider.dart:742`, `scan_meal_section.dart:426`, `tool_dispatcher.dart:1263`. Cloud `nutrition_log_items.quantity_g` becomes meaningless (always 0 unless from search/barcode). Server-side analytics that joins on this column will mis-aggregate. Comment at `tool_dispatcher.dart:1259` says "safe — readers use total_*" but that's only true for our own readers; a future export, weekly-report query, or migration that reads `quantity_g` will break.
- **P1-B · Trial-days arithmetic in device-local** — `ai_coach_provider.dart:253`. Time-zone travel skews by 1 day.
- **P1-C · `_dismiss` in LogFoodSheet search tile-tap fires before any user signal** — `search_mode_body.dart:209` `onLogged()` immediately closes sheet. No snackbar from this path either. (Search sheet via showFoodSearchSheet does have one — UX inconsistency.)
- **P1-D · `food_logger_section.dart:60-65` snackbar copy "Daily AI text log limit reached"** — fires on `gate()` `onFree`, but the gate is reached from `canUse` against the local counter which P0-F can be ahead/behind the server. Server 429 with "food_text_daily_limit_reached" gets a different copy in `nutrition_provider.dart:680-681`. Two distinct error paths, two distinct error strings.
- **P1-E · `MessageLimitNotifier.build` re-scans coachBox on every rebuild** — `ai_coach_provider.dart:195`. O(N) over all chat history every keystroke in the coach screen. Performance smell at >500 lifetime messages.

## P2 — polish

- **P2-A · Custom-food create flow doesn't auto-log** — user expectation after pressing "Save custom food" is often "log it now". Flow forces them to search again. (Out of audit scope, design issue.)
- **P2-B · `_writeFoodLogFromIntent` `uniqueSuffix` is dead** — `tool_dispatcher.dart:1250` says preserved for callers, only used in error path string.
- **P2-C · `_isoDate` in usage_counter is a third copy of the format helper** — should consolidate with `lib/core/utils/ist_date.dart`.

## Most likely root cause of user's reported bug

**P0-A + P0-B in combination.** The user invoked the AI text path (most natural reading of "AI analysis didn't log the meal"), saw the breakdown card, tapped SAVE MEAL. One of three things happened:

1. **Most likely**: save succeeded, card vanished, no confirmation rendered (`ai_breakdown_card.dart:110-128` has zero feedback after the `saveMeal` call), and the user concluded "it didn't log" because they had nothing to anchor on. Then tapping SAVE MEAL again on the now-empty state hit the silent early-return at `nutrition_provider.dart:733` (`if (data == null) return`), reinforcing the impression.

2. Second-most-likely: user tapped SAVE MEAL twice quickly. First tap succeeded but UI didn't catch up before the second tap, which got the silent null-state early return. Same outcome.

3. Less likely but plausible: server returned 429 from the food_text_analysis trigger because the client local counter (`P0-F`) is behind the server count, the analyse path returned an error state (`AiBreakdownData` with `error` set), the breakdown card showed the error tile (`ai_breakdown_card.dart:20-39`), and the user thought tapping SAVE was still valid — but the card has no SAVE button in the error state. They retyped and analyzed again, hit 429 again, gave up.

**Concrete next-step claim**: in `nutrition_provider.dart:731-765`, `saveMeal` should (a) await the WriteResult and check `result.success`, (b) `ai_breakdown_card.dart:110-128` should pop a `Meal saved ✓` snackbar identical to scan_meal_section.dart:449 on success and an actionable error on failure, (c) the early-return at line 733 should be a debug-only assert, not silent.
