# Handbook — durable working rules

This is the **portable** layer of accumulated wisdom from building
ICANBEFITTER. Each entry is a rule that has survived multiple batches
+ generalizes beyond a single bug.

## What lives here

- **Bug classes** — recurring failure patterns + their tells +
  prevention (`bug-classes/`).
- **Process discipline** — workflow rules that prevent self-inflicted
  pain (`process/`).
- **Conventions** — non-obvious cross-cutting standards
  (`conventions/`).
- **Audit methodology** — how we run + verify audits
  (`audit/`).
- **Testing** — what tests can + cannot tell you (`testing/`).

## What does NOT live here

- **One-off corrections** — those stay in `~/.claude/projects/.../memory/feedback_mistake_*.md`.
- **In-flight batch notes** — those stay in
  `~/.claude/projects/.../memory/project_*_inflight.md`.
- **Batch retrospectives** — those stay as `project_*.md` in memory.

The memory dir's role going forward is **scratch + in-flight +
retros**. Durable rules live HERE.

## Frontmatter convention

Every handbook file carries:

```yaml
---
title: <one-line title>
category: bug-classes | process | conventions | audit | testing
source_memory: feedback_<original>.md
last_reviewed: YYYY-MM-DD
---
```

## How to add an entry

1. A new rule emerges in a batch retrospective (`feedback_*.md` in
   memory dir).
2. If the rule survives 2+ batches AND generalizes beyond a single
   bug, promote it.
3. Promotion = port the rule here under the correct category, PII-scan
   (regex for emails, tokens, account IDs, app IDs, project IDs), set
   `last_reviewed`, regenerate `INDEX.md`.
4. The source feedback file stays in memory dir (backwards compat).

## Conventions for content

- Write in the third-person collective voice ("we learned X"), NOT
  "founder said X" — the handbook is portable; the originating
  session shouldn't anchor it.
- Drop project-specific anchors (commit SHAs, batch numbers, dates)
  when they aren't load-bearing for the rule. KEEP them when they
  ARE — e.g., "first surfaced Test #15.3" is useful context.
- Cite the bug-class instances in the body, not just the source memory.
