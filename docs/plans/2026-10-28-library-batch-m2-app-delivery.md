## What M2a delivers, and what it does not

M2a (this plan): the still pictures on the 44 px tiles, the moving animation in the sheet (the calendar day sheet's tile and every active-workout door, which all open `ExercisePlateSheet`), the on-demand delivery path (opening an exercise fetches that ONE file on any connection), the cache, the kill switch. M2b (the draft, OI-354): the hero tile on the focused workout card, the full-screen viewer and the keyboard fold. M2c (the draft, OI-440's second half): the Wi-Fi bulk prefetch of the plan window, the plan-window pin, the daily budget and its alert (spec calls C6, C13, C20). Until M2b ships, an active-workout door opens the animated sheet, which is a complete experience on its own; until M2c ships, the first open of each exercise needs the network (about 0.4 MB, one file). **Done when (M2a):** on a phone and in a web build, signed in: a row with media shows its still in the tile and its animation in the sheet; reduce-motion shows the first frame and a play button; the second open is instant and works offline; a signed-out request and an anonymous session make zero requests; one on-demand file loads on any connection; the cap evicts the least recently shown file; a failed or refused read leaves the still and retries later; the kill-switch combinations of C22 behave as stated and the OFF case restores today's behaviour (the tile AND the sheet); rows with only a plate or only initials are unchanged; every new protection is mutated once (rule 21).

## Review Focus (input classes the tests below pin; the reviewer checks each deliberately)

1. A row whose `media_slug` is a String but `media_version` is missing, 0, a double or a string, or whose slug holds a separator: no delivery attempt, today's plate or initials (Task 4).
2. Sign-out, account switch and delete-account run the REAL `clearAllData()`: the cache still reports the files it holds and the cap still holds (Task 5).
3. Concurrent changes: three `put`s at once keep three entries and an exact `totalBytes` (Task 5).
4. The token is stale: ONE refresh and ONE retry, process-wide cooldown, never a refresh on an absent-object 400 storm or on a 200 that is not a WebP; the token never appears in any log string (Task 6).
5. Two widgets ask for the same file at once; a widget rebuilt 60 times asks once; a slow answer for exercise A landing after the user switched to B must not paint on B (Tasks 7, 9).
6. The cap is breached while several files are cached: the entry with the oldest `shown` goes first, ties by name, and the entry just written never does, even when it alone exceeds the cap (Task 5).
7. (Moved to the M2c draft: Wi-Fi drops during a bulk prefetch.)
8. A truncated file, a file the OS deleted after load, a full disk, a browser with no IndexedDB or one that never answers the open: the view ends on the still, the bytes just paid for are not thrown away, and boot is never delayed (Tasks 5, 7, 9).
9. A file that downloads but cannot be decoded is not re-downloaded on every open (Tasks 7, 9).
10. The kill switch stops DOWNLOADS, not only the pictures: with `disable_exercise_animations` or `disable_exercise_plates` set the repository makes zero requests and zero store reads (Task 7).
11. `read` racing a `delete` or an eviction, and any call before `ready` completes (Tasks 5, 7).
12. Fail-closed state across sign-out and account switch: a refusal caused by "no session" (no token, a null token, an anonymous session, a throwing seam) makes zero requests and arms no back-off the next account would inherit (Tasks 6, 7).
13. The concurrency tests use fakes with SCRIPTED per-call latency, because uniform latency lets an unqueued implementation pass (Task 5).
