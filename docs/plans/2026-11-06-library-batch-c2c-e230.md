2. **`standard_swap ""`** (76/92 convention; the old value names no row; no reader).
3. **Text rewrite** (`coaching_cues`, `common_mistakes`, `warmup_protocol`, `pro_tip`): no cable, no load; progression by tempo only. Draft (no `;`; a node port of the audit gives 0 findings, the current text as bodyweight gives 1, "cable"; max cue 78 characters; seven bodyweight rows already mention "wall"): cues "Stand tall on one leg, hips square, touching a wall for balance if you need it", "Keep the standing knee soft", "Curl the heel toward your glute, thigh staying vertical", "Pause at the top, lower for a slow count of two"; mistakes "Swinging the hip to complete the rep", "Not fully extending the leg on the way down", "Letting the thigh drift forward as the heel comes up", "Dropping the leg instead of lowering it"; warmup "1x10 per leg, slow and easy"; pro_tip "Trains one hamstring at a time, so it shows up side-to-side imbalances a two-legged curl hides. Slow the lowering to 3 seconds once 15 clean reps per leg feel easy". Unchanged: tempo, reps, rest, difficulty, priority_tier, met_value, cal_per_set_est, `breathing_cue`, `variant_family`, `core_levels`.
4. **Injury tags unchanged (`hamstring` only):** E049 and G0599 (loaded curls) carry the same; the old pro_tip calls it a rehab and prehab move; the free curls that add `knee` (E046, E292, G0339) load the knee through an anchored foot or body position. Reviewers attack this (feedback `injury_tag_per_injury_no_kept_safe`).
5. **The edit is a record plus an importer stage, not a hand edit.** `scripts/data/library_e230_retag.json` holds `id`, `gif`, `before` and `after` for the nine changed keys, `frozen_sha256_before` and the decision text; it is GENERATED with node from `git show HEAD:assets/data/exercise_library.json` (never typed: `before` holds U+2014 and U+00D7 that a heredoc or PowerShell write can mangle). `scripts/add_library_batch_c_v15.js` applies it inside its `kept` map as `{...r, ...after}` (key positions kept; `applyMedia` deletes and re-appends its three keys, so run order is irrelevant): it first asserts that `after` and `before` have the same nine keys and that each exists in the row (a typo key would be appended last and `--check` would still pass bytewise) and throws if the record exists but E230 is not in the library (as E274 does at `:266`); equal `before` applies, equal `after` is a no-op, any other value throws (non-zero exit; the importer's failures are uncaught throws, `--check` sets exit code 1).
