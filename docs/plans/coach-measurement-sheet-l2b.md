### A1 — `lib/core/constants/body_measurement_specs.dart` (new; a sibling of the sites registry, which stays untouched)
- `class BodyMeasurementSpec { const BodyMeasurementSpec({required this.minCm, required this.maxCm}); final double minCm, maxCm; }` and `const Map<String, BodyMeasurementSpec> kBodyMeasurementSpecs` keyed by the four tokens, **values written as inline constructor calls** (a flat `{'chest': 1.0, …}` would be a second multi-site literal for the lib-wide scan; the keys test below, not the scan's blind spot, is the protection).
- **Bounds (cm): chest 60-200, waist 50-200, hips 60-200, arms 20-70.** Adult floors, chosen so that the common inch values typed in cm mode (waist 26-49, chest 30-55, hips 30-55, arms 10-19) land **below** the floor and are rejected with the inch hint (B4). That is the "probably inches" threshold of L2a §0: it **is** `minCm`, there is no second field. Residual false-accept zones (a value valid in both units): waist 50-78, chest/hips 60-78, arms 20-27; they need a very large body or a bodybuilder and are listed in §7. Founder-adjustable (D5); the table is the only place the numbers live. Every bound must also be a multiple of 0.1 — a **fixed point** of `roundMeasurementToTenth` — or A3 could pass a value A2 then rejects (a hypothetical arms maximum of 70.25: the parse accepts 70.25, the card shows 70.3, the writer rejects 70.3 and the card freezes); the A1 test below enforces it for every future table edit.
- `bool isValidBodyMeasurementCm(String? site, double? v)` → `spec != null && v != null && v >= spec.minCm && v <= spec.maxCm` (NaN fails both comparisons, ±Infinity fails the range; **no separate `isFinite` term**, which would duplicate the range test and make every single-guard NaN mutant equivalent — RB-6).
- `double roundMeasurementToTenth(double v)` → `double.parse(v.toStringAsFixed(1))`. **Total by construction** (R2B-3, R3B-3): on the pinned Dart 3.11.1 `toStringAsFixed` returns "NaN", "Infinity" and "-Infinity" for the non-finite values and `double.parse` reads them back (probed), so NaN and ±Infinity come back unchanged and then fail the predicate. There is deliberately no `isFinite` guard: it would be dead code no test can redden. The formula `(v * 10).round() / 10` is the one that throws `UnsupportedError` on them, and it is the mutant the totality rows kill.
- `String? measurementRejectionMessage(String tier, String? site, double? v)` → `null` when the site is not in the registry, `v` is `null` or the value is valid; otherwise `'tier=$tier site=$site side=$side'` with `side` = `nonfinite` (`!v.isFinite`), `below` (`v < min`) or `above`. Never the number. One function for every tier (A2, A3, B1); the callers emit `ErrorTelemetry.logEvent('measurement_value_rejected', message: m)`.
- Tests: keys == tokens in **both directions**; every spec `minCm < maxCm`; **every bound is a fixed point of the rounding** (`roundMeasurementToTenth(minCm) == minCm` and the same for `maxCm`, all four sites); a boundary table whose probes are **literals**, not read from `kBodyMeasurementSpecs` (chest 59.9 / 60 / 200 / 200.1, waist 49.9 / 50 / 200 / 200.1, hips 59.9 / 60 / 200 / 200.1, arms 19.9 / 20 / 70 / 70.1 — a table that reads the spec follows a moved value and its mutant stays green); `NaN`, `±Infinity`, `null`, unknown site, `'Waist'` (case) false; `roundMeasurementToTenth` over NaN and ±Infinity (returned unchanged — the totality pin), 49.94 → 49.9, 49.96 → 50.0, 200.04 → 200.0, idempotence; `measurementRejectionMessage` over every combination (exact strings, `null` cases).
