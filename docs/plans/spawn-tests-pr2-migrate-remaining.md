## 2. Design

**D1 — one mechanical rule per site, no new helper surface unless a pattern repeats.** `Process.runSync(exe, args, workingDirectory:, environment:, includeParentEnvironment:, runInShell:, stdoutEncoding:, stderrEncoding:)` becomes `runSpawn(exe, args, why: '<scenario>', workingDirectory:, extraEnv: <only what the scenario ADDS>, remove: <only kept names it DROPS>, allowControl: <control names it sets on purpose>, runInShell:, stdoutEncoding:, stderrEncoding:)`; `Process.run` becomes `runSpawnAsync`; `Process.start` becomes `startSpawn` followed by `reportSpawn(exitCode, stdout, stderr, why)` once the output is collected. A site's old environment map is classified into: (a) the parent minus a filter → deleted, the helper does it; (b) additions (`GIT_CONFIG_GLOBAL`, a `PATH` prefix, `EMAIL`, `HOME`, `PRE_PUSH_FULL`) → `extraEnv`, with `allowControl` naming every control variable among them; (c) removals of a kept name (`HOME`) → `remove`. (d) a wrapper function that threads a caller's `env` map (`...?env`) declares `allowControl` as a CLOSED LITERAL SET of the control names that file's scenarios set on purpose (for example `{'GIT_CONFIG_GLOBAL', 'PRE_PUSH_FULL'}`), never one computed from the map's keys (a computed set declares whatever arrives and defeats the runtime guard); the unit's report lists each file's set. The guard in `hermeticEnvironment` (a control variable in `extraEnv` throws unless declared) is what turns a forgotten declaration into a loud failure. A scenario that needs a RESTRICTED `PATH` (a stub `dart` first, or no `dart` at all) builds it explicitly and the report names it; the common stub-first case is a PREFIX of the parent's path (`'$stub${Platform.isWindows ? ';' : ':'}${Platform.environment['PATH']}'`, an indexed read, which G2 allows).

**D2 — behaviour changes that are INTENDED, and the ones that are not.** (i) The 47 sites with no `environment:` now run with the canonical scrub and `DART_BIN_OVERRIDE` removed (they used to inherit everything): intended, and the unit's evidence is that the file passes both in a clean shell and with the poisoned parent of D6. (ii) A scenario that needs `DART_BIN_OVERRIDE` (the resolver tests, anything that runs `scripts/_dart_bin.sh` on purpose) re-supplies it through `extraEnv` and the diagnose-doc lists those files. (iii) NOT intended: any change to what a test asserts. A unit may not loosen, delete or reorder an assertion; where a hand-written `reason:` duplicates what the helper now prints it stays (a longer failure message is not a regression). ONE exception, and it is a retarget, never a deletion (R2-06): an assertion whose SUBJECT is a local environment builder that D4 deletes (`gate_index_e2e_test` around `_cleanEnv()`, `gate_index_fresh_e2e_test`, `new_worktree_base_test`, and any the units find) is retargeted to assert the same property (no control variable in the result) on `hermeticEnvironment(...)`, the unit lists each retarget in the diagnose-doc, and the retargeted assertion MUST run `hermeticEnvironment(parent: <a synthetic map carrying a name of every control family>)` and assert none survives (R3-06: over the real parent it is vacuous in a clean shell); its mutant weakens the scrub (one prefix removed from `childEnvStrippedPrefixes`) and must redden it.

**D3 — one new helper, decided and written BEFORE wave 1: `runSpawnWithInput`.** 14 of the 20 `Process.start` sites write a stdin payload (section 1 item 5; R2 found a fourteenth, at `batch_close_hook_e2e_test` around line 252, outside the first census's 14-line window); the full "write, close, drain, exit" idiom is repeated far above the threshold of three, so the coordinator adds to `test/helpers/spawn.dart`, with tests in `spawn_helper_test.dart`, `Future<({int exitCode, String stdout, String stderr})> runSpawnWithInput(String exe, List<String> args, {required String why, required Object stdin, String? workingDirectory, Set<String> remove, Map<String, String> extraEnv, Set<String> allowControl, bool runInShell, Encoding? stdoutEncoding = systemEncoding, Encoding? stderrEncoding = systemEncoding, Map<String, String>? parentEnvironment, void Function(String diag)? report})`. **[stdin] is an `Object`: a `String` is written, a `List<int>` is ADDED as raw bytes** (R2-01: `review_gate_hash_raw_bytes_test` and `review_gate_staged_content_not_working_tree_test` feed `git hash-object --stdin` raw bytes, the subject of f4d1b7; a String-only helper would force a lossy decode or leave those sites outside it); any other type throws an `ArgumentError`. It calls `startSpawn`, writes, awaits `stdin.close()`, drains stdout and stderr CONCURRENTLY (`Future.wait`), awaits the exit code, calls `reportSpawn`, returns the record. **It does NOT reproduce every existing site exactly** (R2-12, corrected): some sites drain stderr and stdout one after the other and some discard stderr; the helper drains both at once and reports both, which cannot deadlock where a sequential drain did not and changes no assertion (the outputs a test reads are the same bytes). No `try/catch` around the stdin write: a site that tests a broken pipe or a kill keeps `startSpawn`. Its tests: a String payload and a raw-bytes payload (0x00, 0xFF and a lone 0x80 survive unchanged) reach the child; a child that writes more than a pipe buffer to BOTH streams before reading does not deadlock (mutant M9: drain stderr only after the exit code); a failing child's diag carries stderr; the control-variable guard still throws; a poisoned `parentEnvironment` does not reach the child; a type other than String or List<int> throws. The encodings follow `runSpawn` (R3-10: a site that decoded with `utf8.decoder` passes `stdoutEncoding: utf8`, a `SystemEncoding().decoder` site keeps the default; they differ on Windows only). **The exemptions from the helper are CLOSED (R3-07):** the concurrent-git sites of `git_lock_concurrency_test`, `batch_close_hook_e2e_test`'s explicit drain-then-timeout deadlock test (the second start), `discipline_hook_main_sync_e2e_test`'s kill test, and true fire-and-forget children; each stays `startSpawn` followed by one `reportSpawn(...)` after the output is collected, listed per unit with the line that proves it. EVERY OTHER stdin site uses `runSpawnWithInput`, including `git_safety_hook`'s two sites that write stdin and read only the exit code (they gain the stderr report: leaving them on the exit code alone keeps the class-2.90 hidden-stderr shape). No other helper surface is added.

**D4 — `dartBinOf()` copies and per-file scrubs are deleted, not wrapped.** Each file imports `../helpers/spawn.dart` and calls `dartBin()`; a file keeps no local function whose job is "build an environment" or "find dart".

## 3. The strict site guards (`test/contracts/spawn_sites_guard_test.dart`)

The guard reads files with `Directory.listSync` and spawns NOTHING (a guard against spawns that spawns would be circular, and it keeps the guard out of its own G1).
