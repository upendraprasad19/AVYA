## 2. Units

### U1 — merge-safe push (one payload builder, a shape-independent fingerprint)

New pure file `lib/core/services/sync/measurement_push_rules.dart` (the `exlog_push_rules.dart` precedent; `sync/**` is platform tier), no Hive, no network:

- (the file imports only the constants file; no `DateTime.now`, no `payload_hash_index` literal, no `.update(`/`.delete(` call near a `from(`, so Gates G1/G2 stay quiet)
- `measurementLegacyPayload({userId, date, log, createdAt})` → `{user_id, date, <every site in registry order: log[site]>, notes: log['notes'], if createdAt != null: created_at}`. This IS the shape every shipped APK sends; key order equals HEAD's.
- `measurementFingerprintContent(legacy)` → the same map with every site that is not a finite `num` replaced by `null` and `notes` that is not a `String` replaced by `null`. For every record the in-repo writers can produce (`logMeasurement`, restore and pull copy numbers and Strings; a site that is a numeric String or bool, or a non-String `notes`, has no in-repo writer and would merely re-push once) it is **identical** to the legacy payload, so `SyncFingerprint.of(content)` equals HEAD's stored fingerprint: **no one-time re-push after upgrade and no re-push when the kill switch is toggled.** (v2 fingerprinted the new body and therefore re-pushed every stored day once; round 2 showed that re-push is a stale-overwrite trigger with nothing to heal.)
- `measurementMergeSafeBody(legacy)` → `{user_id, date, <only finite-num sites>, notes only if String, created_at if present}`, or `null` when it holds no site and no `notes` String (an empty row would be created otherwise). `0` is pushed like any finite number (only the cloud or a restore can produce it; `logMeasurement` rejects `<= 0`, and L2b's bounds make it moot).
- `mergeCloudSitesIntoLocal(existing, cloud)` → the pull's rule (fill a site only where the local value is null), extracted so it is testable without the unreachable pull.

`_syncMeasurements` becomes: read `SyncFlags.measurementMergeSafePushEnabled` **once per pass**; per record build `legacy`; `body = mergeSafe ? measurementMergeSafeBody(legacy) : legacy`; `if (body == null) continue;` (after `liveKeys.add(date)`, which stays first so `commit` does not prune that date); `pushIfChanged(date, () => SyncFingerprint.of(measurementFingerprintContent(legacy)), () => upsert(body, onConflict: 'user_id,date'))`. The upsert stays inside the `pushIfChanged` closure (Gate G1).

- **Kill switch** `disable_measurement_merge_safe_push` → `SyncFlags.measurementMergeSafePushEnabled` (default ON, `catch` → ON). Set: the body is `legacy` byte for byte (the old path is the same builder minus the filter, not a second copy) and the empty-row skip is off. It is a debug/test lever per §1; the diagnose-doc says so and says why the switch is kept rather than deleted (CLAUDE.md §4.6 requires the old path to stay reachable; the old shape is the defect, so no operational use is claimed). Toggling it changes only the body of pushes that happen anyway.
- `created_at` is unchanged: still sent, so on a conflict the last pusher's `created_at` wins (as today); the pull's 24 h window and restore's `since` are unaffected.
- `notes`: pushed iff a `String` (so `''` is a value and a future "clear" stays expressible); nothing in the app sets notes today.

**Residuals, stated in both directions and in full (rounds 1-2):**
1. **The old shape is still in the fleet.** Old APKs push nulls (and OI-297 reports an out-of-repo Telegram writer; this repo cannot show what it sends). A new build's skip index does not re-push an unchanged day, so a blanking by an old client is healed only by the next local edit of that date. A `sync_epoch` bump is **not** recommended for a signed-in-on-several-devices user (`docs/operations/SYNC_EPOCH_RESYNC.md:54`, the very population that suffers blanking).
2. **Stale overwrite.** The merge-safe body still sends every site this device holds. If another device corrected a site for date D (cloud now 81) and this device still holds 82 (restore skips present dates; the pull fills only null sites), a later push of D from this device regresses the cloud to 82. Triggers: the user adding a site to D here; a `sync_epoch` `clearAll`; `disable_measurement_hash_skip` set; **the first push of every restored day** (restore records no fingerprint, `sync_health.dart:507-516`, unlike the exlog restore in L1a-3; the content is identical to the cloud's at that moment, so this is harmless unless another device wrote in between); an offline-retried push after another device wrote. Disjoint sites survive every ordering. This is the founder's standing "last sync or write wins" (L1a, 2026-10-06) applied to this table; the alternative (a per-site pending set the push sends and clears after a confirmed push) is the L2b entry criterion above, not an L2a change, because with 0 rows nothing can be overwritten yet.
