## 0. What this plan is, and what changed

**What Landing C is.** Two more doors to the Landing B sheet, behind the same flag `enable_body_measurements` (default OFF, so no user sees either):

- **E3 — a "Body measurements" card at the top of Profile → Progress comparison** (`ProgressComparisonScreen`). Per site (chest, waist, hips, arms): the latest value and the day it was taken; with two or more entries that hold the site, the change since the FIRST entry that holds it; and a permanent "Add measurements" button that opens the Landing B sheet. It is the first on-demand door: every Landing B door needs a due prompt, so after a save nothing reopens the sheet for 28 days.
- **E4 — an action chip in the AI Coach chat**, in its own slot between the quick prompts and the input bar, shown while a measurements prompt is `due` or `baseline`, with its own dismiss X wired to the same dismissal as the Home banner's X. A tap on the chip opens the Landing B sheet. It cannot send a message.

**Why a separate landing.** Both hosts hide their logic where a test cannot reach it (D7, answered 2026-10-12: "Cut E3/E4 into Landing C"). Landing C keeps each host edit to one line (E3 also fixes the screen's empty state, C2b) and puts the logic in widgets that own their flag and state checks (the Landing B slot pattern).

**Changes against the umbrella's §3b text, each verified against the merged code (§1):**

1. **`bodyMeasurementsProvider` gains one field, `entries`.** "First entry that holds a site" is a PURE function of `entries` (`HealthReadService.firstBySiteOf`). (§3 C1)
2. **The card's numbers follow the unit the sheet uses, through ONE shared, total method** (`MeasurementWriteNotifier.preferredInches()`, which the sheet calls too), and the delta is the difference of the two DISPLAYED numbers. The umbrella showed one unit; Indian tape measures are mostly inches. (§3 C1, C2)
3. **Card geometry is built against the real host.** The Progress screen is a sub-route of the Profile shell branch, so its body is about 100 dp shorter than a bare `Scaffold` (an 80 dp `NavigationBar`, a 24 dp status inset, a 56 dp AppBar: about 480 dp of 640; 408 dp of 568) and shrinks again behind the sheet's keyboard. The card has a pinned header (never inside a scroll region) whose text scale is clamped, a scrolling tile region, a cap that always leaves the snapshot list 150 dp, a header-only compact mode, and a host that drops the card when the body is too short. Every constant is derived in §3 C2 and measured by a test. (R1A-2, R1B-1, R1C-5, R2A-1, R2B-1, R2C-4)
4. **A failed history read does not look like "never measured"**, the account-swap window shows nothing, and an empty history shows no sentence. (§3 C2)
5. **Both slots own their flag check** (Landing B's pattern); OFF creates no measurements provider. (§3 C3)
6. **The chip has its own X** (question D10) and is ONE tap target with ONE screen-reader node. (§3 C3; R1B-7, R1C-8, R2A-2, R2B-2)
7. **The screen's empty state becomes scrollable, as a planned unit (C2b).** (§3 C2b)
8. **`StatSnapshotService.snapshotManual` stays as it is** (Landing B's D1, ledger `SNAPSHOT-DEVIATION`, still the founder's call): nothing reads `UserStatSnapshot.measurements`. (question D1)

**Not in Landing C:** the flag flip (own commit, its own ×2 review and B-pass, after OQ-L2a, OI-310 and the OI-305 acknowledgement), `/build-apk`, the device check, L2c (the per-site pending set, `lib/core/services/sync/**`), OI-304 (the dead `InsightCard`), photos, body-fat estimation, any change to the Take Snapshot action, the sheet's behaviour (its unit expression moves into the shared method, same value, and its now-unused import goes), or the prompt rules.

## 2. Design principles carried over from Landing B

Neutral numbers (no good or bad wording or colour on a change; a waist increase is not bad for someone bulking); no guilt or streak-loss framing; the entry is optional and never PRO-gated; Hive-first (the card shows with the network down); every widget that reads user data watches what it needs itself, so it rebuilds on an account swap; a slot OWNS its flag check and an OFF build creates no measurements provider; every control is at least 44 dp with button semantics and ONE screen-reader node (`excludeSemantics: true` over its visuals); every string assertion in a test uses a literal, never the constant it checks.

## 3. Units

### C1 — `entries`, `firstBySiteOf`, and a total `preferredInches()`
- `BodyMeasurementsState` gains `final List<MeasurementEntry> entries` (default `const []`); `build()` sets it to the `history` it already reads; the failed-read and anonymous-token states keep the empty default. Still NO value equality. Its class doc gains `entries`.
- `HealthReadService.firstBySiteOf(List<MeasurementEntry> newestFirst)` — PURE, static, next to `latestBySiteOf`, with the same debug assert (a release build strips it: the only producer of `entries` is `measurementHistory()`, newest first). For each site of `kBodyMeasurementSites` it scans from the OLDEST end for the first entry holding the site; returns `Map<String, ({double cm, String date})>`; a site never measured is absent.
- `MeasurementWriteNotifier.preferredInches()` returns `lastUnitInches() ?? !UserRepository.instance.getUnitsMetric()` and is **total**: one `try/catch` inside the method falls back to `false` (centimetres) and logs `unawaited(ErrorTelemetry.logEvent('measurement_unit_read_failed', message: 'stage=unit'))` (a LOW event; Landing B's events are emitted the same way and are not registered anywhere else). `BodyMeasurementsSheet.initState` calls it instead of its inline expression (the one edit to Landing B code; same value; the sheet's `user_repository.dart` import is removed: an unused import is an analyzer warning that aborts a push) and the card calls it. One expression, one guard: a cross-surface test asserts the card and the sheet resolve the same unit for the same stored state, and a row with a throwing read covers both. It lives in the provider file, which already watches the auth token (G11), so no new file needs the token watch.

### C3 — E4: `MeasurementChipSlot` and the host line

## 9. Residuals (stated, not hidden)
- **OFF is not byte-identical to the last build, in two stated ways.** (1) The empty state is a scroll view under the `Center` (C2b): the same rects when it fits. (2) Each host gains a node: the frame adds one Element and no render object (it returns the child itself); the chip slot adds one zero-size render box. Harmless; listed in `AGENT-WEB-CHECK`.
- `AiCoachScreen` and `ProgressComparisonScreen`'s snapshot list cannot be pumped past their singletons: the hosts' lines are presence-only pins; the logic they call is covered by the frame, card, slot and end-to-end tests.
- The card refreshes on mount, on Retry, after a save, after a chat write and on a background-restore tick (through Home). A Telegram pull while the screen is open is not shown until one of those; pull-to-refresh and Take Snapshot reload the snapshot list only.
- The device's metric setting is written only on the Profile screen, below Progress, so it cannot change under a mounted card.
- Inch-mode deltas are differences of rounded displays, so two stored values 0.1 cm apart can show "no change" in inches; and 60.0 cm (chest, hips) and 70.0 cm (arms) print 23.6 in and 27.6 in, figures the sheet refuses as typed (G7).
- The header label shrinks (`FittedBox`) and the header's text scale is clamped at 2.0 so the header cannot outgrow its floor; the label's full text stays in the semantics node. The tile region uses the user's full scale.
- **As built (B-pass, 2026-10-12): where the build departs from this plan.** The departures and the reasons are recorded in the closure ledger rows C2, C2B, C3 and BPASS-RECORDED and in `docs/reviews/coach-measurement-surfaces-bpass.md`: the 0.6 em fixture became a 700 dp host plus a text scale of 0.6 over Ahem (the real JetBrains Mono advance), the header button is 48 dp high (the derivation above says 52), `kCardMarginTop` / `kCardMarginBottom` are public constants, the card has a branch for an unbounded host (no `Flexible`, never compact), the empty state guards `hasBoundedHeight`, and the chip slot reports its first frame (`onShown`) so the host can scroll a chat that was at its bottom back to its bottom.
- The chip hides on composer focus and returns after every reply; its X is the silence (D10). A person who dismissed the Home banner has silenced the chip too; the card is unaffected. Retry on a persistent failure replays the same caption.
- A body under 286 dp (the soft keyboard up behind the sheet, a very short web window) drops the card and shows the snapshot list alone; between 286 and 400 dp the card is header-only; the snapshot list keeps its scroll position across both thresholds.
