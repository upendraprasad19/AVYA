## Rulings

- **R1. Slug.** `<4-digit gif number>-<kebab(ledger entry name)>` (example `0103-barbell-standing-ab-rollout`), built from the ledger entry's `name` field; R10 (g) checks the same string from `ledger_id` (kebab of the id after its first five characters) because CI has no ledger, and the builder asserts the two agree (they do for all 616 today). **kebab(s)** = lower-case, replace each run of characters outside `[a-z0-9]` with one `-`, trim `-`, refuse an empty result (so `Farmer's Walk` is `farmer-s-walk`; the function is permanent because object names are immutable). Table regex `^\d{4}-[a-z0-9]+(-[a-z0-9]+)*$`. One slug per gif NUMBER, so N06 and G3643 share `3643-...` and one file. Only ledger entries with a 4-digit number are mappable in M1: a map or export entry naming `table-row-clean` (or any non-numeric id) is refused. Alias numbers (6000 to 6013) are ordinary numbers with their own file; a row mapped to an alias and another mapped to its canonical upload the same bytes twice, at most 14 files, accepted and not de-duplicated. The object name is `<slug>_v<media_version>.webp`; **in M1 `media_version` is 1 for every file** and a changed file under an existing slug is refused by the builder (objects are immutable); versioning, the `x<owner>` slug form for animations without a gif number, and the swap rule are M1c.
- **R2. `media_source`** is the constant `wardroom`. The table's `_meta.origin` records the upstream: "AI recreation of the GIF set in `assets/exercise animations/forgetrainer_animations/gifs`; licensing risk accepted by the founder (D9, 2026-10-21)".
- **R3. Provenance table** `scripts/data/library_media_v16.json` (canonical JSON, keys sorted, no timestamps). `_meta`: `origin`, `ledger_completed_at` (the ledger's run-level `completedAt`, carried as text), `bucket` (`exercise-media`), `webp_bytes_max` (1,500,000), `old_rows` (`null`, or `{sha256, entries, omitted}`: the hash of the export the builder last consumed, the number of `E` rows it WROTE, and the number of export entries it dropped because their slug is taken down), `taken_down` (list of slugs, see R13). `rows`: id -> slug. `files`: slug -> {`status`: `active` (some row maps to it), `unmapped` (no row maps to it, for example a held row) or `taken_down` (listed in `_meta.taken_down`; never mapped); `gif` (4-digit); `ledger_id`; `source_gif_sha256`; `webp_sha256`; `webp_bytes`; `thumb_sha256`; `thumb_bytes`; `frames`; `versions`: a list holding exactly `{media_version: 1, webp_sha256, webp_bytes, file}` in M1, where `file` is the ledger's `outputs.animation` value (relative to `--wardroom-dir`, forward slashes, starts `webp-720/`, no `..`), so the upload tool needs no ledger}. The list shape is kept so M1c appends without a schema change; `media_version` is its last entry. Built by `scripts/build_library_media_v16.js` (`--write` / `--check` / `--prune-only`; flags `--table --map --ledger --wardroom-dir --library --old-rows --out`; `--write` writes `--table` in place, `--out` writes elsewhere and is the seam the tests use). **Derivation:** `G`/`N` ids come from the media map, the ledger, the files on disk and the shipped library (`--library`, so held rows and rows without an animation are excluded by construction); `E` ids come from `--old-rows` when given, else are carried from the existing table. A rebuild never drops a `files` entry (provenance), never changes a recorded sha, and stops naming the slug when the animation or the thumbnail on disk differs from the table's recorded sha or from the ledger's validation sha (`animationValidation.SHA256` / `thumbnailValidation.SHA256`; `thumb_bytes` is read from the disk file, so the thumbnail provenance M2 will rely on is verified too). A `taken_down` slug is never mapped: the builder omits every row that would map to it. `--wardroom-dir` defaults to the primary checkout's folder, resolved with `primaryRoot()` from `.claude/token_path.js` (`git worktree list --porcelain`, the repo's tested resolver that is correct for linked worktrees, `--separate-git-dir` and submodules) and can be passed explicitly. `--check` and the normal mode need that folder, so they are local commands; `--prune-only` needs no folder.
