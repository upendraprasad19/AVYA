**Pure seam (new top-level functions, unit-tested directly):** `validateSetInputs(loggingType, weightText, repsText, durationText, distanceText)` returns a STRUCTURED result `SetValidation { ok | failure(field: weight|reps|duration|distance, kind: empty|outOfRange, message) }` (field order and messages extracted VERBATIM from `_validateSetInputs :291-321`; the existing method delegates), `setsToLog(numSets, checkedKeys, exIdx)`, `logButtonLabel(...)`, `seedForAddedSet(...)`, `loggedVolumeKg(...)`.
**Structured validation drives label and focus (verified rules):** `weight_reps` checks weight then reps; `weighted_bodyweight` checks reps ONLY (weight never blocks it, so its blocked label is `Add reps`); `bodyweight_reps` reps; `timed` duration; `cardio` duration only (distance never blocks); `distance` distance. Label is `Add <field>` for an `empty` failure, `Fix <field>` for `outOfRange` (reps 61+); the tap focuses the failing field's node. Test 4 pins label and focus per logging type, including reps-empty-with-weight-present and out-of-range.
**`logSets(exIdx, Set<int> idxs)` (additive writer):** bounds-checks `exIdx < exercises.length` and each idx `< numSets` (a stale idx can never create a phantom set, cf. `completeWorkout :1830-1838`), ONE `copyWith`, only ADDS keys, an empty/duplicate set is a no-op with NO side effects (no toast, no persist, no advance). Idempotence is decided from `ref.read(activeWorkoutProvider)`.
**LOG sequence:** (1) validate EVERY unchecked set with the pure function; any failure => nothing logged, failing rows marked, button in blocked state. (2) `_captureSetValues` for EVERY set of the exercise (checked and unchecked, closing the `+`-on-partially-checked gap). (3) `onLogExercise(exIdx, idxs)` in `screen.dart`: `notifier.logSets` then a LOG-specific advance helper derived from `ref.read` (not the build-time `data`): clear `_focusedExerciseIndex` once the exercise is done; superset partner scroll as today. (4) ONE persist through a NEW ON-only helper `_persistActiveStateFor(count)` that takes the count from `ref.read`; the shared `_persistActiveState` (reads `widget.data`, takes a `setIdx`, `:234-268`) is untouched so OFF is unchanged (OI-355 stays open for the OFF path). LOG passes the last set index for the weight/reps snapshot text. **Warm-up sets:** LOG checks and validates ALL unchecked sets including warm-up-flagged ones (else `isExerciseDone` never flips); `completedSets` still excludes warm-ups; label `{n}` counts unchecked WORKING sets; an all-warm-up exercise shows `{n}` = 0 and LOG still completes it (label falls back to `LOG ✓`).
**Input guard:** owned by `_ActiveWorkoutScreenState` (cards are separate States and the advanced-from card collapses, so a card-level guard cannot protect the NEXT card): a `DateTime` stamp taken from the existing `nowWall()` seam (`train_provider.dart:1805`, fakeable) set when an advance happens; `onLogExercise` returns `bool` and ignores a call within ~400 ms of the stamp. It blocks LOG only: header taps, `+` and FINISH under the thumb stay unguarded by design (a mis-tap there is visible and reversible, a mis-LOG is not until U1b). 400 ms suffices because a non-superset advance does not scroll the list (the layout change is the card collapse itself); superset partner scroll is delayed 200 ms and lands inside the window. **Wiring is testable (round 4 P1-2):** the whole `onLogExercise` decision (guard check, `logSets`, advance computation, stamp) is extracted into an injectable `LogExerciseController` (plain Dart class: takes the notifier, a clock function, and returns a result enum `ignored | logged | noop`); the screen only delegates and applies the result (focus/scroll/toast). A `false`/`ignored` result skips the persist and the LOGGED repaint. **Clock (P2-1):** the guard uses a monotonic `Stopwatch`-style seam passed into the controller, NOT `nowWall()` (which is frozen under dev time-travel `setTestClockTo`, `ist_date.dart:~33,65`, and would swallow every LOG after the first advance); tests advance the fake explicitly.
**Reactive button:** the label/blocked state is built inside a `ListenableBuilder` whose `Listenable.merge` is constructed in `build()` from the live controllers of the unchecked sets (not cached in `didUpdateWidget`; the screen rebuilds at 1 Hz so the cost is negligible and membership changes cannot go stale).
