## Problem (measured 2026-11-21)

The `pubspec.lock` on `main` (changed by the Dependabot PRs #20, #21 and #9, merged 2026-11-21) cannot be honoured by Flutter 3.41.4, the version CI, Vercel and `.fvmrc` pin. On a clean checkout `flutter pub get --enforce-lockfile` exits 65 and a plain `flutter pub get` rewrites it: "Changed 31 dependencies", 127 insertions / 47 deletions, 19 version changes, 11 additions and 1 removal, nothing else touched.

**Cause, measured (F15, F16):** the lock `main` held at `2c2b3496`, before the Dependabot PRs, passes `--enforce-lockfile` (exit 0); at `a6c1825d`, the PR #20 merge, it fails (exit 65, "Would change 31 dependencies"). The committed lock asks for `riverpod` and `flutter_riverpod` 3.4.3, which pub.dev lists with `sdk: ^3.12.0`, while Flutter 3.41.4 bundles Dart 3.11.1; it also asks for `meta` 1.19.0 where the SDK's own `packages/flutter/pubspec.yaml:18` pins `meta: 1.17.0` (`:19` `vector_math: 2.2.0`; `packages/flutter_test/pubspec.yaml:20,21` `test_api: 0.7.10`, `matcher: 0.12.19`, against the committed 0.7.14 / 0.12.20). So the file was written by a resolver that accepts Dart 3.12 (an inference from the pub.dev facts above; the lock's own `sdks.dart` still reads `>=3.11.1 <4.0.0`), and the pinned toolchain cannot resolve 3.4.3. The committed lock also contradicts itself: its `sdks.flutter` was `>=3.38.4` (`git show origin/main:pubspec.lock`, line 1801) while it carries `image_picker` 1.2.4 and `onesignal_flutter` 5.8.0, whose pubspecs in the pub cache both declare `flutter: ">=3.41.0"`, which the regenerated lock records (line 1881). A resolver would have written `>=3.41.0`, so the committed file was a partial edit by the bot, not plain resolver output. It also carries `analyzer` 14.7.0 although `.github/dependabot.yml:33-34` ignores `analyzer` (whether Dependabot applies an `ignore` to a transitive entry is not established).

Consequences observed in this session: the `/build-apk` run for `1.0.0+50` left a dirty tree after `pub get`; `retire_worktree.dart` printed `KEEP [1 uncommitted file(s)]` for a worktree whose pre-push analyze had run `pub get`; and the dependency set of the `+50` AAB was whatever `pub get` resolved that day, not a committed file.
