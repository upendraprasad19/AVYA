## Decisions

**D1. Flip = delete the flag.** `sessionSetBudgetEnabled` is removed; `generateV4` always builds the `SessionBudgetContext` and runs the allocator. No `disable_*` kill switch is added: the build-time plan's contract is "the flip commit deletes the OFF paths", and a kill switch would keep the OFF code alive. Rollback is a revert of this PR. A stored Hive value `enable_session_set_budget = true` left by a developer is inert after the delete (no reader).

**D2. Delete the OFF paths listed above, in one commit with the flip.** `PeriodizationEngine.apply` and `VolumeTitration.applyToWeeks` take `budget` as required (their only production caller is `generateV4`, round 1 confirmed: previews, repeat pins, plateau and the injury top-up all go through `generateV4`); `WarmupCooldownSelector.attach` keeps it nullable (templates). The unbudgeted body of `apply` also holds the cycle multiplier, the 4-set minimum, the physique-focus +1 and the triggered-deload stash; **coverage-loss rule:** before deleting it, list every live feature whose proof test only exercises that body (physique bring-up `disable_physique_focus_bringup`, triggered-deload stash, graded progression, wave reps, plateau +1) and confirm or write an equivalent test under `_applyBudgeted` (Task 2). Where a unit test called the OFF behavior of a helper (for example `VolumeFilter.filter` without `keepAllSlots`), the test is rewritten to the budgeted behavior or deleted with the code it tested; it is never loosened.

**D3. Display.** Budgeted minutes are the only answer for a readable day. The three null-day fallbacks (Home, Train `estimatedDuration`, swap `_estimateSeconds`) keep their old numbers (`sets x 2.5` minutes, 45 for a day with no sets, the `sets x (60 + rest)` seconds sum) in ONE shared function, with one test per caller proving an unreadable day still gets a number and `shortenDay` does not throw or return 0. Decided here, not left open: a stored day whose exercises all fail the library lookup is priced from its own fields by the budgeted model when it can (the existing `rowsByName` miss path), else by the fallback. A day built by the OLD generator (4-set minimums) is priced by the new model: no stored value changes meaning (round 1 P2-4, confirmed), and testers only.

**D4. Wording.** The Edit Profile chips (`edit_profile_screen.dart:1147`) and, if onboarding shows minutes (`onboarding_provider.dart:889` writes the field; Task 3 checks for a picker), the same picker read `Up to 30 min`, `Up to 45 min`, `Up to 60 min`, `Up to 90 min` and the section keeps its `Session Duration` title; the plan-change summary line (`Session: 45 min -> 60 min`) is unchanged. Train and Home keep `~N MIN` (they show the day's modelled length, which is already an estimate). Founder can veto the chip wording in the PR (Open question O3).

**D5. Quads (ask 3).** Evidence above, plus round 1's sharper reading: the quad-bearing day (Legs A) is out of time (88.1 of 90 minutes) and the time went to Deadlift 4, Hanging Leg Raise 4 and calves 6 while Quads sat below its floor, because admission gives every admitted exercise its base sets before the grow pass. So two real levers exist: (a) the split (a quad slot on Legs B), (b) an allocator policy (withhold base sets from at-or-above-floor non-lead groups, or trade a set on the same day). Neither is shipped here: (a) is a product call on the split, (b) is a new allocation policy that would change every generated plan and needs its own measured design. This batch puts a measured line in the report (below-floor counts by group and cause, which the report already prints: Quads has 1078 `co_group_limited`, 1227 `time_limited`, 669 `cap_limited`) and records both options to the founder. Terminal state `blocked_on_user`, reason: choose (a), (b) or neither. It is not called a split-shape fact.

**D6. Migration (ask 4), a SEPARATE commit after the apply go.** Gate 14 needs a ledger entry for every migration file, the paired-commit gate needs the file and the entry together, and Gate 39 hashes the file as applied (edits after apply, comments included, need a new migration). So the file and the ledger entry must not be committed before the live apply, or the ledger would claim an apply that did not happen. Plan: reserve the number with `sh scripts/mint_migration.sh <slug>` now (no commit); on the founder's explicit apply go, apply, then commit the file, its `scripts/migration_ledger_hash.dart` hash and the ledger entry together. A comment is not a column change, so `backups/live_schema_columns.json` is untouched. Until the go: `blocked_on_user`. The code PR does not depend on it.

**D7. B1 `enable_core_list_pool` stays OFF.** The recorded flip criteria are not met (`ship_dark_pending_review.yaml:285-333`, quoted by run): emergencyAnyLevel non-zero in 2 golden personas (shoulder-injured bodyweight 4-day intermediate, phases 1 and 2) and in 58 of 576 multi-injury runs (after Batch C1); refilled in 34 of 576; retired rows in the multi-injury built lists E144, E261, E254, E294, E271, E234; the OI-401 (R9) top-up question is unanswered; the golden top-up set is four ids, E271, E261, E254, E234.
