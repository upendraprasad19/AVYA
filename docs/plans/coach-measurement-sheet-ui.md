### B1 — `HealthWriteService.logMeasurements` (batch writer; `logMeasurement` is not edited in B)
`Future<WriteResult> logMeasurements({required DateTime date, required Map<String, double> sites, required WriteSource source})`:
1. **Validate the whole map first, in a loop that only reads, before touching the box** (all-or-nothing): `sites` non-empty; every key `isBodyMeasurementSite`; every value, after `roundMeasurementToTenth` (total — NaN and ±Infinity come back unchanged and fail the NaN-safe predicate), passes `isValidBodyMeasurementCm`. A violation → **one** `measurement_value_rejected` event per call (`tier=writer`, the first offending KNOWN site, `measurementRejectionMessage('writer', site, value)`, no value in the message) and `WriteResult.fail(...)`; a map holding only unknown sites emits no event (the helper returns null for an unknown site) and still fails; nothing is written and no `put` happens inside the loop (R4B-5).
2. `dateStr = istDateStr(date)`; key `measurement_$dateStr`; lock `"$dateStr::measurement"` — the same key `logMeasurement` uses; the two methods never nest, so the non-re-entrant `_acquireLock` (`health_write_service.dart:400`) cannot deadlock. Under the lock: `record = measurementRecordWith(box.get(key), dateStr: …, sites: rounded, source: …)` (A's builder keeps every site not in `sites`, restore-written explicit nulls included, and stamps `date`), **one** `await box.put`, then **one** fan-out (`syncMeasurementsNow` + `pushSnapshot`, `:243-244` in the single-site sibling). Errors → `recordNonFatal(reason: 'health_write_service_log_measurements')` (seam `ErrorTelemetry.debugOnRecordNonFatalForTests`, `error_telemetry.dart:72-80`).
3. No `notes` parameter (L2a §0 carried one): no client writer sets `notes` (`git grep` over the write and read services and the handler finds none), the merge-safe push already handles a String `notes` that arrives from elsewhere, and an unset `notes` stays untouched.
4. Registry, in the **same commit** (Gate 7: every `Future<…> log[A-Z]…(` in `lib/core/services/*.dart` must be named in a registry `method:` string): `logMeasurements` joins the `method:` string of the `health_write_service` concept (`sot_registry.yaml:7336`) **and** the `health_write_service.dart` writer entry of A's concept `body_measurement_value_bounds` (`:15200`, `method: logMeasurement`): that entry's `line_range: 212-255` is **extended** to cover the new method (a method added below `logMeasurement` does not move 212-255, it leaves the new code uncited), and every pin below `logMeasurement` in the file, the `health_write_service` writer range among them, is repointed (R4B-11). The new method builds its key as `measurement_$dateStr`, an interpolated literal that Gate 50 cannot see (G12), so the registry entry and the batch behavioural test are the only protection of that writer.

- **The error state has no door of its own** (B4, R5B-10a): every door needs a non-`none` prompt and `loaded == false` makes the prompt `none`, so the caption and Retry appear only if the read fails after the sheet opened (or through the debug-only dev button, which needs no prompt), and Retry helps only a transient failure (it does not reopen a closed box or change the token).
- **A profile without `onboarding_completed_at` never gets the baseline prompt** (B3 rule 5; 1 of 33 cloud rows and pre-Unit-D local profiles); a measured user without it still gets `due` (R5B-10b).
- **The "Last:" hints and the saved-line delta read the provider cache** (R5B-9b): a Telegram or pull entry does not refresh it until the next rollover, restore tick or app start (`CHAT-PULL-STALE`), so a hint can be up to a day old. Opening the sheet does not invalidate the cache (that would be a second refresh path with its own mutants for a window that exists only for out-of-app entries, 0 rows today); the delta is always printed in centimetres so a one-decimal inch rounding can never show "31.9 → 31.9".
- **The Weight-sheet link reflects the prompt at the moment the sheet opened** (B6, R5B-11): the decision is latched in `initState`; a prompt change while the sheet is open does not add or remove the link, and the autofocused field is never rebuilt by it.
- **The token guard on the unit write has one instant-wide gap** (B2; observed by R6B under "could not verify"): `authUserIdTokenProvider` is a cached `Provider<String>` that recomputes only after the auth-state stream or the owner listenable notifies, while `wrapUserScopedBox` reads the live auth uid, so in the instant between the live uid changing and the provider recomputing `tokenNow` can still equal `tokenBefore` while the box is already the empty stub and `MigratedKey.write` falls back to `configBox`. The consequence is that one user's cm/in preference is readable by the next account on the same device until sign-out clears `configBox`; it is a display unit, not health data (ledger `MIGRATEDKEY-FALLBACK`).
