## 2. Design

- **D1 — one helper, `test/helpers/spawn.dart`** (naming per `docs/naming_conventions.md`; new glossary rows appended). API, chosen to cover every shape in 1.6 without changing what any test does:
  - `Map<String,String> hermeticEnvironment({Map<String,String>? parent, Set<String> remove = const {}, Map<String,String> extra = const {}, Set<String> allowControl = const {}})`. **Order is fixed and pinned:** (1) `scrubbedChildEnvironment(parent ?? Platform.environment)` (control variables and `EMAIL` out), (2) the helper's own default removals (`DART_BIN_OVERRIDE`, D2), (3) `remove` (case-insensitive; how a scenario drops a KEPT variable such as `HOME`), (4) `extra` last (the scenario declares what the child may see; a scenario that sets `GIT_CONFIG_GLOBAL` after the strip works, as `discipline_hook_main_sync_e2e_test.dart:48-50` needs). **Guard (round 2, finding 6): a control-set key in `extra` throws `ArgumentError` naming the keys unless the call lists it in `allowControl`**, so a whole-parent map passed as `extra` (`{...Platform.environment, 'GIT_DIR': x}` at `token_path_resolver_test.dart:196`, about 30 `Map.from(Platform.environment)` builders PR 2 will meet) cannot silently put every control variable back: the scenarios that set a control variable deliberately (`GIT_DIR`, `GIT_CONFIG_GLOBAL`/`_NOSYSTEM`, `PRE_PUSH_FULL`, `CONTRACT_SWEEP_SKIP`) say so by name. Honest limit: in a CLEAN shell a whole-parent spread holds no control keys and passes; PR 2's static guard adds the rule "no `Platform.environment` inside an `extra:`/`extraEnv:` argument".
  - `String spawnDiag(int exitCode, Object? stdout, Object? stderr, String why)` = `"$why\nexit=…\nstdout=…\nstderr=…"` (the PR #79 format, whole, no truncation); a `List<int>` value is rendered as `N bytes` plus its UTF-8 decode with malformed bytes allowed, so a raw-bytes site (`review_gate_staged_content_not_working_tree_test.dart:289`, a `Process.run` with `stdoutEncoding: null` for `hash-object --stdin`) cannot crash the reporter.
  - `ProcessResult runSpawn(String exe, List<String> args, {required String why, String? workingDirectory, Set<String> remove, Map<String,String> extraEnv, Set<String> allowControl, bool runInShell, Encoding? stdoutEncoding = systemEncoding, Encoding? stderrEncoding = systemEncoding, Map<String,String>? parentEnvironment, void Function(String)? report})`: always `includeParentEnvironment: false`, then reports, returns the result. The encodings are declared with `= systemEncoding` defaults, not `?? systemEncoding`, so an explicit `null` (raw bytes) survives. `runSpawnAsync` for the `Process.run` sites (it must preserve the same raw-bytes `null`). For the 20 `Process.start` sites: `Future<Process> startSpawn(...)` (control-variable-clean environment only) and `reportSpawn(exitCode, stdout, stderr, why)` that the caller invokes after collecting output (PR 2's plan lists per start site whether stderr is collected: collecting it where a test does not is a small, benign change in what that test does, and the PR says so). All three entry points are exercised directly in PR 1's helper test even though only `runSpawn` has a PR 1 caller.
  - **The default reporter (round 1 R1-05, round 2 finding 5).** `report` is nullable and `runSpawn` resolves `report ?? defaultSpawnReport`, where `defaultSpawnReport(String diag, int exitCode)` does: inside a test zone, `printOnFailure(diag)` (prints only if THAT test fails, and buffers silently otherwise); with NO current invoker (a spawn from `main()` at load time), `print(diag)` **only when `exitCode != 0`**, so a successful `which dart` probe in nine files stays silent while a failed one is visible. Tested through `runSpawn` itself with no `report:` argument (not only through the function): in a null-invoker zone (`runZoned(..., zoneValues: {#test.invoker: null})`, a faithful stand-in: `zone.dart:681-683` lets a null in a child zone shadow the parent's invoker) a success prints nothing and a failure prints; and inside a PASSING test, with a zone-captured `print` that keeps the invoker, the default prints nothing (printOnFailure buffers), which kills the "print as default" mutant behaviourally instead of by a source pin.
  - `String dartBin()` (the one shared copy of the `dartBinOf()` found in 13 files: honours `DART_BIN_OVERRIDE` read from the TEST process's own environment, else `which`/`where dart`, never `Platform.resolvedExecutable`, which under `flutter test` is the `flutter_tester` binary and hangs the suite, `oi_numbering_lib_test.dart:284`); the two migrated files use it, PR 2 deletes the other 11 copies.
  - `why` is **required**, so a site cannot be wired without a label. `parentEnvironment` is a test seam (Dart cannot mutate its own environment, so a poisoned parent can only be injected).
- **D2 — deny-list, not allow-list.** The scrub stays "parent minus control variables", extended to the classified set in 1.5: the two external-prefix and six repo-owned-prefix families (`GIT_`, `GITHUB_`; `CONTRACT_SWEEP_`, `PRE_COMMIT_`, `PRE_PUSH_`, `DISCIPLINE_HOOK_`, `MINT_OI_`, `MINT_MIG_`), the exact names (`PUSH_BEFORE`, `ALLOW_RAW_GIT`, `ALLOW_MAIN_COMMIT`, `FOUNDER_APPROVED_NO_VERIFY`, `SUPABASE_ACCESS_TOKEN`, `SUPABASE_ACCESS_TOKEN_FITNESS`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `RAZORPAY_KEY_ID`, `_SKIP_RENDER_CHECK`, `ANDROID_DEVICE_ID`) and the external reader `EMAIL`. **`SUPABASE_` is deliberately NOT a prefix** (class 2.56's rule is "never widen an exact name to a prefix"; Supabase owns that namespace): a sixth `SUPABASE_*` read in a script fails the manifest until classified, which is the derived test doing its job. **The helper additionally removes `DART_BIN_OVERRIDE` by default** (the two-level rule of 1.5), a constant of the helper, not of the canonical scrub. An allow-list ("only PATH, HOME ...") was rejected: the founder also runs these tests on Windows (SystemRoot, PATHEXT, COMSPEC, the Flutter/Dart cache variables) and this VPS cannot verify that, so an allow-list would trade a known gap for an unverifiable break at 126 sites.
  - **The recursion guard (round 1 R1-07, round 2 finding 10).** `CONTRACT_SWEEP_NESTED` exists so a test that runs the real pre-push hook cannot recurse (`contract_sweep.dart:14-16`). Stripping it from a test child is the point of this PR, and it moves the guard from "inherited" to "declared". **The pin's detector is specified, not "names pre-push.sh":** a test file is *recursion-capable* when its comment-stripped source contains a shell EXECUTION of the hook (`sh scripts/pre-push.sh`, `bash scripts/pre-push.sh`, `exec sh scripts/pre-push.sh`) or a spawn argument naming `scripts/contract_sweep.dart` without `--flutter-bin`; such a file must contain `CONTRACT_SWEEP_SKIP` or `--flutter-bin`. Today's matches: `pre_push_analyze_always_e2e_test.dart:121,238` (declares `CONTRACT_SWEEP_SKIP` at `:68`) and `contract_sweep_e2e_test.dart:180` (always passes `--flutter-bin`). Files that merely READ or COPY `scripts/pre-push.sh` as text (`contract_sweep_wired_test`, `hook_gate_placement_test`, `pre_push_blast_radius_failsafe_test`, `pre_push_matches_ci_invocation_test`, `analyze_narrower_than_lib_lib_test`, `check_hooks_installed_e2e_test`, `blast_radius_content_rule_wired_all_scripts_test`) never execute it and are not flagged by this detector; a fixture push in `safe_push`/`mint_oi`/`mint_migration` tests fires no hook: `setup-hooks.sh:57` installs the hooks into the working repository's own common hooks directory, and a fixture repository made by `git init` has none.
