**Ruling 2 (d25, the quad slot: the fit key's reach).** `fitApplies = pattern != 'core'` (was: compound slot and not
core). Its position is unchanged (after the sub-focus and type keys, directly before `priority_tier`), so the fit key
only orders rows of equal sub-focus and type match; an isolation row still outranks a compound row in an isolation
slot. Where R3 (a) has already reduced an isolation slot to like-for-like implement rows, the key is uniform.

**Ruling 3 (d25, phase 1: a bodyweight row gives way to the loaded row that will be picked, when that row fits the
slot at least as well).** `slotMatch(r) = 2 * subMiss(r) + typeMiss(r)` (the same two tests as the sub-focus and type
keys; lower is better). In phase 1 and a non-core slot, `topFit` = the first row, by the keys that follow (key d, the
sub-focus, type and fit keys, `priority_tier`, foundational, R5, then id; under Ruling 12's emergency the easier-gap
key first, as in the sort), among the rows the user can load (`fits`)
that will not be skipped: not demoted, not soft-avoided, and not in `walkedNames`. `walkedNames` is a new
`rankedPool` parameter (default empty): `_pickCoreList` passes the same lowercase `avoidNames` set it hands to
`_selectCandidate` / `_preferNovel` (`exercise_selector.dart` `fill`: the hard avoid set, the soft avoid, L6's demoted
names; the hard avoid set carries the previous phase's names, the Upper-day variety names of OI-458 and the plateau
names, `exercise_selector.dart` `avoidA` / `avoidB`), so `rankedPool` knows which rows the
walk will pass. New key, inserted directly BEFORE key d: `!fits(r) && slotMatch(topFit) <= slotMatch(r) ? 1 : 0`
(`slotMatch(topFit)` is 4 when there is no `topFit`). Meaning: the pick is either `topFit` (a loaded row that matches
the slot at least as well as every bodyweight row pushed behind it) or a bodyweight row that matches BETTER than
`topFit`. Among rows of equal foundational status, never a loaded row of worse match than an available bodyweight one
(key d still decides across foundational status in phase 1, as today: a foundational loaded `topFit` beats a
non-foundational bodyweight row that matches better, exactly as in r0) (the round-2 case: a bodyweight
right-type row A, a loaded wrong-type row B, a loaded best row C that is avoided: `topFit` is B, B matches worse than A,
A is not pushed, A is picked, as in phase 2). A gym user's loaded rows keep their order (the key is 0 for each); a
bodyweight user is unchanged (no `topFit`).
