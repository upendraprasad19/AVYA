# d9b3e7 - PRO next phase never built after a restore

See the YAML frontmatter for the full diagnosis.

## Root cause (one line)
The only automatic advance runs on the splash, fire-and-forget, BEFORE the restore; on an empty store `isPro()` (local Hive) and `isPhaseExpired()` (false when plan_end is null) make it a silent no-op, and nothing re-ran it after the restore.

## Evidence status
The splash-no-op mechanism is a hypothesis consistent with the code and with the client_errors timeline (local PRO set after the restore); no event existed to prove it for the founder's tab. The new `pro_phase_ensure` events make the next occurrence observable. The streak "1 DAY" is NOT diagnosed here (Piece B).

## Fix
See `proposed_fix`. Plan: `docs/plans/2026-10-16-pro-phase-advance-ensure-current.md` (v10).
