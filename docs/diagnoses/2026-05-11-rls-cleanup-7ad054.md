# Audit H-30 + H-40: RLS policy cleanup

## Bug

**H-40:** rank_ladder has RLS enabled but zero policies → deny-all for any authenticated client. Reference data (11 rows) becomes unreadable.

**H-30:** promo_code_uses had INSERT policy `"Service role can insert promo uses"` with `roles=public, with_check=true`. Despite the name, NOT scoped to service_role — any authenticated user could insert audit rows directly.

## Fix

Migration 054:
- CREATE POLICY rank_ladder_public_read (SELECT TO anon, authenticated USING true)
- DROP + CREATE promo_code_uses_no_client_insert (INSERT TO authenticated, anon WITH CHECK false)

The WITH CHECK (false) pattern blocks all RLS-bound roles. Service role bypasses RLS unconditionally — Edge Function inserts keep working.
