  The plan-review keystone gate (scripts/check_plan_review_record_exists.dart) grants two "nothing here needs a record" exemptions from the CHANGED PATH LIST of a commit or merge: a bare version bump (isVersionBumpCommit) and a Dependabot manifest-only merge (dependabotDiffIsManifestOnly). ## Summary

Two exemptions in the keystone gate compare a commit's changed paths with a short allow-list. The paths were trimmed first, so a file named " pubspec.yaml" (leading space) was the real pubspec as far as the decision went. The fix is to compare exactly, to read git's paths NUL-separated as raw bytes, and to stop trimming anywhere on the path from `git diff` to the predicate.

## Root Cause

A normaliser (`trim`) was applied to the INPUT of a security decision. It was added for robustness against stray whitespace in `git diff` output, which the author of the exemption treated as noise; but a path is data, and its whitespace is part of its identity. The same instinct had put a whole-output `.trim()` in the git helper, which silently strips the first path's leading space even when no predicate trims.

## Fix

See `proposed_fix`. Found by a probe in B2, which made the exemption reachable from merges; fixed in that batch rather than left for later because the same predicate guards the direct-push path that is already live.
