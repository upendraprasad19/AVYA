# Bug D.3 — Streak-freeze pill shows `x/y`

## Symptom

The streak pill on home/train/nutrition headers showed `❄ <available>` (single digit). PRO user with 1 remaining had no signal that capacity was 3 — visually identical to a free user with 1. A user at 0 remaining saw the snowflake section grey but lost any sense of "you can earn back to N." Founder direction (2026-05-10): switch to `x/y` ladder format.

## Root cause

`StreakBadge` (lib/features/home/widgets/streak_badge.dart:76) rendered only `widget.freezesAvailable`. Max was implicit and not surfaced. `WardStatusStrip` and the three caller screens did not pass max.

## Fix

1. Added `freezesMax` parameter to `StreakBadge` (default 1 for back-compat).
2. Render switched to `'${widget.freezesAvailable}/${widget.freezesMax}'`.
3. Added `streakFreezeMaxProvider` in `home_provider.dart` returning 3 (PRO) or 1 (free) via `SubscriptionService.instance.isPro()`.
4. `WardStatusStrip` threads `freezesMax` from caller into `StreakBadge`.
5. Three callsites updated: home_screen.dart, train_screen.dart, nutrition_screen.dart all pass `ref.watch(streakFreezeMaxProvider)`.

Subscription tier change re-renders the pill via the provider invalidation path that already fires on `SubscriptionService.onStateChanged`.
