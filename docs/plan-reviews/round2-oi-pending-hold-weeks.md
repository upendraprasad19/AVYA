## Convergence judgement

**Not converged, but for a different reason than rounds 1-3.** The three prior passes (self-review, B-pass, Hermes-lens-inline) each found real logic/coverage defects in the *hold-identity and telemetry-filtering code itself*, and this round's deep trace of the same four areas came up clean — the code-level fix is now solid: I could not make the migration guard, the row-derived labels, or the rolling-context recount fail under adversarial mutation. What this round found instead is a **new class**: the batch's own paper trail has drifted from the code during the batch's own self-correction cycle. Both findings are instances of the same root cause — the same one OI-133's own "root-cause note worth keeping" already names for a different pair of files ("deriving [a fix/taxonomy] and not sweeping its consumers is the writer/reader drift class arriving from the reader side"): a correction was made in one artifact (the migration file's comments, moving "three reads" to "four") and not propagated to its siblings (`sot_registry.yaml` still says three) or re-verified against its own manifest (the ledger's hash went stale the moment the file was edited past the point a prior review had checked it). Given this is now the **third** round in a row to find a materially new defect class (round-1/round-2/round-3 logic bugs → this round's paper-trail bugs), and the pattern each time is "the last correction pass didn't sweep everything it touched," I'd treat this as a signal that the unit's *size*, not just its logic, is the problem: FOB-1 and FOB-5 are two features on one branch with a growing tail of self-corrections, and each correction pass is now spending more effort re-verifying its own prior corrections than shipping new fixes. Per §4.12.1's own guidance ("when successive reviews keep surfacing new material issues, that is the signal the unit is too large — split it and ship the smallest converged piece"), I'd recommend against a round 4 on this same branch and instead recommend closing out the two paper-trail fixes here (both are small, mechanical, no-code-risk edits) as their own tiny commit, then treating FOB-5's still-open items (OI-133's redeploy-credentials blocker, the 92-row cleanup) as follow-on work rather than reasons to keep re-reviewing this branch as a whole.
